# 서비스 업무 흐름 설계

## As-Is (관찰한 범위)
1. 교육생이 일정/과제/프로젝트/상담을 문의한다.
2. 운영 담당자 또는 강사가 공식 공지·일정표를 확인하거나 구두로 안내한다.
3. 개인별 판단이 필요한 경우 추가 확인이나 상담으로 이어진다.

※ 실제 운영 과정 전체를 관찰한 것은 아님.

## To-Be (제안·구현 예정)
1. Google Forms로 문의를 접수한다.
2. 문의와 접수 시각을 Sheets에 저장한다.
3. AI가 문의 유형과 답변 근거 유무를 판단한다.
4. 근거가 명확한 경우 답변 초안을 제시한다.
5. 근거가 없거나 개별 상담·개인정보 문의라면 담당자 확인으로 구분한다.
6. 담당자가 검토·수정한 뒤 처리 상태를 업데이트한다.

## 권한 및 예외 처리
- AI가 개인 출결 내역에 접근하거나 추측하지 않음
- 공식 문서가 없으면 그럴듯하게 지어내지 않음
- 자동 발송 금지, 초기 MVP는 담당자 검토 필수
- 모델 오류/도구 실패 시 '검토 필요' 상태로 기록하도록 구현 목표 설정

## 앞으로 확정할 것
- 최종 자동화 도구·API
- 문의 ID 부여 규칙
- 검토 상태(예: 접수/검토 대기/확인 중/완료) 정의
- 저장 방식과 중복 처리 기준
