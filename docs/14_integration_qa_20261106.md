# MOA | AI 에이전트 통합 QA 및 개선 기록

검증일: 2026-11-06
마감: 2026-11-11 18:00
상태: 부분 검증 완료 / 통합 개발 진행 중

## 1. 테스트 목적

교육생 문의를 접수하고 AI 에이전트가 공식 자료를 검색한 뒤,
답변 가능 여부에 따라 운영자 검토 대상으로 기록하는 흐름을 검증한다.

실제 교육생의 개인정보가 아닌 가상 문의를 사용한다.

## 2. 구현 및 확인한 기능

- Google Forms 신규 문의 접수
- Google Sheets Watch New Rows 실행
- Get Range Values를 이용한 원본 행 재조회
- 최초 감지 문의와 재조회 문의의 일치성 필터
- Data Store의 문의ID 존재 여부 조회
- Make AI Agent의 공식 안내 검색 도구 호출
- 승인된 공식 안내 재조회 및 원문 추출
- Google Sheets 문의관리_대장 저장
- 정상 안내와 검토 필요 Fallback 경로 분리
- Data Store의 처리 기록 Key 등록 및 재조회

위 기능의 개별 실행 또는 제한된 사례 실행을 확인했다.
전체 시나리오의 모든 예외와 안정성이 검증된 것은 아니다.

## 3. 실제 확인한 오류

### QA-01. 원본 문의ID와 저장 내용 불일치

관리 대장에 저장된 MOA-FORM-5가
현재 원본 응답 시트의 5행 내용과 일치하지 않았다.

추가 확인 중 접수 시각과 행 번호가 서로 어긋나는 현상도 관찰했다.

정확한 원인은 확정되지 않았다.

개선:
- 원본 행 재조회 모듈 추가
- 최초 감지 내용과 재조회 내용의 비교 필터 추가
- AI 입력 및 관리 대장 문의내용을 재조회 데이터로 변경

검증:
- 특정 정상 사례에서 최초 감지와 재조회 값의 일치를 확인

한계:
- 원본 행 변경 시 식별자 안정성은 미검증
- 과거 누락 문의 자동 복구는 미구현

### QA-02. AI 분류와 실행 행동 불일치

실제 AI 응답:
category = 정보 확인 필요
guide_id = MOA-G003
next_action = USE_APPROVED_GUIDE

정보 확인 필요로 분류했지만 승인된 안내를
사용하겠다는 모순된 결과가 반환되었다.

개선:
- Router 정상 경로 조건에 category와 next_action 동시 검증
- 정상 조건을 만족하지 않으면 Fallback으로 분기
- Fallback은 답변 초안을 빈칸으로 저장
- AI 판단값과 실행 행동을 관리 대장에 기록

검증 사례:
MOA-FORM-8의 D열이 비어 있고
E열에 정보 확인 필요, USE_APPROVED_GUIDE,
MOA-G003이 기록된 것을 확인했다.
F열은 검토 대기였다.

한계:
- Fallback은 정상적인 확인 필요 문의도 포함한다.
- 모든 Fallback을 AI 오류로 간주할 수 없다.
- AI 판단 자체가 정확해진 것은 아니다.

### QA-03. 신규 문의 감지 결과 불일치

일부 테스트에서 의도한 과제 제출 문의 대신
최종 프로젝트 문의가 실행 결과에 나타났다.

또 다른 실행에서는 새 데이터가 없다는 메시지가 나왔다.

2026-11-06 17:56:10 실행은 처리 모듈까지 진행됐고
17:57:03 실행에서는 신규 데이터가 확인되지 않았다.

후자의 결과는 앞선 실행 이후 새 문의가 없었을
가능성이 있으나 모든 원인을 확정하지 않았다.

### QA-04. 중복 처리 방지의 검증 범위

Data Store:
MOA_Processed_Inquiry_Keys

MOA-FORM-5에 대해 다음을 확인했다.

- 등록 전 Exists=false
- Key 등록 성공
- 등록 후 Exists=true

정상 안내와 Fallback 경로에
처리 기록 등록 모듈을 각각 구성했다.

한계:
- 이미 기록된 문의가 전체 시나리오에서
  실제 차단되는 회귀 테스트는 아직 미완료
- Google Sheets 저장과 Data Store 등록 사이에
  장애가 발생하면 중복 위험이 남는다.
- Key는 관리 대장 등록 상태이지 검토 완료가 아니다.

## 4. Fallback 경로 검증

2026-11-06 17:56:10 Make 실행 로그에서 다음을 확인했다.

- Watch New Rows 실행
- Get Range Values 실행
- AI Agent 실행
- 승인 안내 경로 필터 미통과
- Google Sheets [19] Add a Row 실행
- Data Store [20] Add/replace a record 실행

관리 대장에서 MOA-FORM-8의 보류 기록을 확인했다.

그러나 의도한 팀당 인원 문의가 아닌
최종 프로젝트 진행 방식 문의가 저장됐다.

따라서 팀당 인원 문의의 정상 이관 성공으로 기록하지 않는다.

AI 에이전트의 별도 확인 요청 등록 도구 [10]도
해당 실행에서 호출 성공을 확인하지 못했다.

## 5. 기획 판단과 사용자 가치

문제:
AI가 근거 부족 상황에서도 잘못된 처리 행동을
선택하거나 기존 문의와 다른 내용을 기록할 수 있다.

기획 판단:
- AI 판단을 그대로 승인하지 않는다.
- 분류와 실행 행동을 별도로 검증한다.
- 모순이 발생하면 답변을 보류한다.
- 운영자가 검토할 수 있도록 판단값을 남긴다.
- 실제 외부 답변 발송은 자동화하지 않는다.

사용자 가치 가설:
운영자가 잘못된 안내를 확정하기 전에
AI 판단의 모순을 확인할 수 있다.

실제 운영 효율과 사용자 만족도는 측정하지 않았다.
