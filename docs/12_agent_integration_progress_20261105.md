# MOA | AI 에이전트 통합 개발 기록

작업 기준: 2026-11-05
기록 정리: 2026-11-06
최종 제출 준비 마감: 2026-11-11 18:00

## 1. 사용자 문제와 기획 목적

기업교육 운영자는 반복적인 공통 문의뿐 아니라 공식 안내가 부족하거나 개인별 판단이 필요한 문의도 처리한다.

MOA는 AI가 모든 질문에 답변하는 서비스가 아니라, 승인된 근거를 조회하고 답변 가능한 문의와 사람의 확인이 필요한 문의를 구분하는 서비스로 기획했다.

운영자의 실제 업무 시간 절감이나 도입 의사는 아직 검증되지 않은 가설이다.

## 2. AI 에이전트 검증 결과

기존 Make AI Agent 시나리오에서 다음 도구의 실제 호출을 확인했다.

- search_approved_guide: Google Sheets에서 승인된 안내자료 검색
- register_confirmation_request: 담당자 확인 요청을 Google Sheets에 등록

에이전트의 판단 결과에 따라 서로 다른 도구가 호출되는 것을 확인했다.

승인된 안내자료를 사용하는 경로에서는 별도의 Google Sheets Search Rows 모듈에서 안내ID와 승인상태를 다시 확인한다.

검증 사례:
- 가상 안내자료 MOA-G001 조회 성공
- 담당자 확인 요청 실제 행 등록 확인
- MOA-G003 미승인 상태에서 확인 요청 경로 확인
- MOA-G003 승인 후 공통 안내 경로 확인
- 승인된 MOA-G003의 안내 원문과 approved_reply_text 일치 확인

위 결과는 제한된 가상 데이터에 대한 테스트이며, 전체 문의 유형의 정확성이나 운영 안정성이 입증된 것은 아니다.

승인된 자료 목록에서 적절한 자료를 선택하는 정확도와 도구 오류 처리는 추가 검증이 필요하다.

## 3. 재처리 및 답변 오류 개선

기존 재처리 시나리오에서 MOA-3 문의를 새로운 행 없이 갱신했다.

AI가 공식 자료에 없는 메뉴를 안내하던 문제를 발견했다.

프롬프트 수정 이후 테스트에서 다음 답변을 확인했다.

교육 플랫폼에서 과제를 제출하려면 '과제 제출' 메뉴를 이용하시기 바랍니다.

이는 해당 사례의 개선 확인이며 모든 AI 응답의 정확성을 보장하지 않는다.

## 4. 신규 문의 접수 연동 진행 상황

시나리오: MOA - Forms Intake Agent

완료:
- Google Sheets Watch New Rows 모듈 추가
- AI_교육운영_문의관리_MVP 스프레드시트 연결
- 설문지 응답 시트1 연결
- 기존 마지막 문의를 시작 위치로 설정
- Make AI Agent Run an agent 모듈 추가

진행 중:
- 기존 에이전트의 Instructions 및 도구 재사용
- 신규 문의 데이터를 에이전트 Input에 매핑
- 신규 문의 1건의 실행 테스트
- 처리 결과와 근거의 통합 저장

현재 신규 에이전트 모듈은 추가된 상태지만, 기존 도구 설정과 입력 연결은 완료되지 않았다.

자동 실행은 안전성 검증 전까지 Inactive로 유지한다.

## 5. T13 및 BR-B 재활용 방향

T13:
- 문의 접수 및 목록 화면
- 답변 수정, 검토 승인, 처리 완료
- 근거 부족 문의 보류
- 승인된 답변 수정 시 승인 해제

현재 T13은 규칙 기반 브라우저 데모이며 MOA AI 에이전트와 통합되지 않았다.

BR-B:
- AI 답변과 공식 근거 비교
- 근거 없는 안내와 후속 공지 약속에 관한 검토 규칙
- QA 사례 및 답변 검수 정책 참고

BR-B는 모든 AI 답변의 의미를 자동 검증하는 도구가 아니다.

## 6. 기획 의사결정

결정 1: AI가 외부에 답변을 자동 발송하지 않도록 한다.
이유: 근거 부족 및 개인정보 관련 문의에서 운영자의 확인이 필요하기 때문이다.

결정 2: 승인된 공식 안내를 다시 조회한다.
이유: AI가 존재하지 않는 메뉴나 절차를 만들어낸 오류가 발견되었기 때문이다.

결정 3: T13의 운영자 검토 UX를 재활용한다.
이유: 검토 및 승인 기능을 처음부터 재구축하기보다 기존 구현을 활용해 핵심 서비스 흐름에 집중하기 위해서다.

결정 4: 고급 통계, 멀티테넌트, 결제 및 자동 발송은 후순위로 둔다.
이유: 신입 서비스기획 취업용 포트폴리오에 필요한 핵심 기능과 검증을 우선하기 위해서다.
