# MOA | T13 운영자 콘솔 실제 연동 QA

> 검증일: 2026-11-10 (KST)  
> 문서 상태: 지정된 가상 테스트 데이터에 대한 운영자 검토 흐름 검증 완료 / 서비스 전체 통합 QA 진행 중  
> 범위: T13 로컬 운영자 콘솔 ↔ Supabase Auth ↔ `moa-operator-api` ↔ `public.moa_inquiries`

## 1. 검증 목적

AI 문의 관리 결과가 실제 데이터베이스에 저장되어 있을 때, 운영자가 로그인한 뒤 문의를 조회하고 검토 상태를 변경한 다음 다시 조회해도 변경 내용이 유지되는지 확인한다. 테스트에는 **가상 문의 및 가상 공식 안내자료**만 사용하며 실제 교육생에게 메시지를 보내지 않는다.

## 2. 확인한 환경

- 운영자 웹: 로컬 `http://localhost:8765/` (T13 실제 AI 문의 검토 영역)
- 운영자 서버: Supabase Edge Function `moa-operator-api`
- 데이터 저장소: `public.moa_inquiries`
- 검증 문의: `MOA-API-TEST-001`, DB `id=2`
- 유형: **고정 JSON으로 저장한 가상 QA 문의** (실제 Make AI 실행 데이터가 아님)
- 선택된 가상 승인 안내: `MOA-G001 / v1.0`

## 4. 검증 중 발생한 문제와 구분

### 4.1. 운영자 API HTTP 503

- 최초 비인증 GET에서 HTTP `503`, `{"error":"Operator API not configured"}` 확인
- 함수 설정 조건상 `MOA_OPERATOR_USER_ID` 또는 기본 서버 환경변수 누락 가능성 확인
- Supabase Edge Function Secrets에서 `MOA_OPERATOR_USER_ID` 등록 후 HTTP `401 Unauthorized` 확인
- **판정:** 비로그인 요청 차단 동작까지 확인. 다른 계정의 권한 거부, 토큰 만료 동작은 별도 테스트 필요

### 4.2. 로컬 접속 오류

- 시연 중 `localhost:8765` 접속이 `ERR_CONNECTION_REFUSED`로 실패
- 로컬 서버를 다시 실행한 뒤 콘솔 접속 재개
- **판정:** 접속 오류가 있었으나 해당 시점에서 처리 완료 요청이 실행됐다는 증거는 없음

### 4.3. 처리 상태가 다른 것처럼 보임

- 앞선 웹 화면에서 `추가 확인 요청` 및 오전 9:41 변경 시각 표시
- 별도로 실행한 SQL에서 `처리 완료`, 오전 9:44:56 변경 시각 확인
- 이후 운영자 웹의 실제 문의 영역을 다시 조회하자 `처리 완료`로 표시됨
- **판정:** 최종 상태는 웹과 DB가 일치한다. 이전 화면이 달랐던 근본 원인(오래된 조회 상태, 작업 순서 등)은 확정하지 않으며, **웹 저장 버그가 재현됐다고 주장하지 않는다**.

## 5. 실행한 SQL 조회

```sql
SELECT
    id,
    source_ref,
    review_status,
    reviewed_draft IS NOT NULL AS has_reviewed_draft,
    reviewed_at,
    updated_at
FROM public.moa_inquiries
WHERE source_ref = 'MOA-API-TEST-001';
```

이 쿼리는 읽기 전용이며 데이터를 변경하지 않는다.

## 6. 검증 범위의 한계와 남은 작업

- `MOA-API-TEST-001`은 **고정 JSON 기반 테스트 건**이므로 실제 Google Forms → Make AI Agent → Supabase → 운영자 검토·승인까지의 전 구간을 동일 건으로 시연했다고 표현하지 않는다.
- 실제 Make AI 처리 결과 `MOA-FORM-9`는 Supabase에 저장되고 운영자 화면에서 조회·보류 처리됨을 확인했으나, 원본 행 번호 식별자 충돌 문제는 미해결이다.
- Google Forms 고유 Response ID 기반 식별자 전환은 아직 통합 완료 전이다.
- 운영자 API의 다른 사용자 권한 차단, 세션 만료, 동시 수정 충돌 등은 별도 QA가 필요하다.
- 실제 교육 담당자 사용자 테스트, 실제 업무 효율 지표, 외부 발송 기능은 검증되지 않았다.
- 최종 포트폴리오에는 **가상 데이터 기반 검증 범위**를 명시한다.

## 7. 서비스기획 관점 정리

AI 분석 결과를 화면에 표시하는 데서 끝내지 않고, **사람이 답변 초안을 확인·수정하고 승인하거나 보류한 결과를 서버에 저장한 뒤 재조회하는 흐름**을 검증했다. 테스트 도중 503 설정 누락과 로컬 서버 연결 문제를 구분해 원인을 좁혔고, 상태가 다르게 표시된 사례는 DB 조회와 웹 재조회를 통해 최종 저장 결과를 대조했다.

> 핵심 메시지: 근거 중심 AI 분류 + 운영자 최종 판단 + 저장 상태 재확인. 다만 실제 서비스 전체의 안정성을 입증한 것은 아님.
